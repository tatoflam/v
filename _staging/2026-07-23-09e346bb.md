## Change 1: support-new-progress-format（archive 済み `6e92024`）

背景: FY26_27 中野区本町5丁目 / FY26_29 きつね塚通り前 の Jooto「進捗状況」タスクが
新フォーマットに移行され、旧タスクと併存。現行 grabber は旧タスクを拾い続けるため、
FY26_27 は実際には新タスク 10/16 チェック済みなのにレポート・writeback には
旧タスクの凍結状態しか見えていない実害が発生していた。

### 調査で判明した事実
- 新チェックリスト名は `マイルストーン  [ ◎：開始時にチェック ] [ ◉：完了時にチェック ]`
  （現行 grabber の完全一致 `マイルストーン` にマッチしない）
- 新フォーマットは 16 項目・工程名が全面刷新（`◎ 1次計画期間` `◉ 基本図FIX` `◉ 下付（決済）` 等）。
  旧 15 項目と 1:1 対応しない
- Jooto API はチェックリストの UI 表示順を返さない（`position` フィールドなし・作成時刻降順のみ）
  → 並び順は config を正典とする

### ユーザ確定のマッピング決定（design.md D2）
- 旧 `躯体形状` → 新 `2次計画期間`（躯体形状は 2 次計画期間中に作成する成果物、構造KO の前提）
- 旧 `仮受付` → `仮受（意匠 / 設備）` + `仮受（構造）` の 2 軸 fan-out
- 旧 `済証交付` → 新 `下付（決済）`
- Milestone シートに列が無い 4 軸（基本設計期間（意匠）/ 基本図FIX / 仮受（構造）/ 図面修正期間）は
  `grid_row: false` で一旦除外（Milestone シートは今後フォーマット変更予定）
- 軸順は中野区本町5丁目の実配置（構造キックオフ → 基本設計期間（意匠）→ 基本図FIX）を正とし
  config に固定。グリッドは 14 行（新 12 軸 + 旧専用 2 軸）

### 実装（テスト 462 pass、コミット: Plugins-Meguru `bb74bc3` / 本リポ `8887426`）
- `config/milestone_mapping.yaml` schema **v5**: `phase_axes` 18 軸、`resolve_label_axes()`
  （新ラベル単一 / 旧ラベル fan-out）、正規化に先頭 ◎/◉ 除去
- jooto-grabber: `進捗状況` タスク複数併存時の決定的選択規則
  （新フォーマットチェックリスト優先 → task id 最大）。`progress_checklist.json` に
  `format` / `task_id` / `checklist_id` を記録
- pm-master-writer: diff を軸レベルに変更（フォーマット切替時も偽遷移なし）、
  1 軸 → 複数列書き込み、`checklist_id` 不一致で `format_transitions` を audit 記録
- 週次レポートの工程グリッドを phase_axes 駆動 14 行に切替

## Change 2: broadcast-new-progress-format-checklist（コミット: Plugins-Meguru `3703201` / 本リポ `4dec9dc`）

ユーザ依頼: 新フォーマット「進捗状況」をテンプレート（task id 37391035 固定）から
フォルダ「PM（確認申請中）」の 27 案件へ複製、旧タスクは `進捗状況(old)` へリネーム。

### 設計の要点
- `--target-boards` 明示 allow-list（英数正規化前方一致、アーカイブ済み除外、曖昧一致は error）
- Write Guard に `rename_task` を追加 — ただし計画時登録の (board_id, task_id) →
  固定名 `進捗状況(old)` の完全一致辞書のみ許可（任意更新は解禁しない）
- チェック状態 seeding: 旧チェックリストのチェック済みラベルを v5 軸マッピングで
  新項目の初期チェック状態に移行（全未チェック複製だと次回 writeback で Milestone
  巻き戻し事故になるため）+ writer 側にフォーマット切替検知時の巻き戻し抑止の二重防御

### 本番障害と復旧（人手削除 → 再実行）
- **障害**: Jooto API がチェックリスト項目を作成時刻降順で返すため、テンプレ UI の
  ドラッグ調整済み並び順が取得できず、**24 ボードに誤った項目順で作成**してしまった
  （リネーム・チェック状態移行は正常）
- **復旧**: writer は削除操作を物理禁止しているため、誤順 24 タスクの削除は
  ユーザが Jooto UI で人手実施 → 修正版（作成前に `phase_axes` 宣言順へ並べ替え）で再実行。
  削除漏れ 2 件（FY26_10 世田谷大原 / FY26_11 東尾久4丁目）も追加削除 → 再実行で完了
- **教訓**: seeding の移行元にリネーム済み `進捗状況(old)` も探索対象に追加
  （再作成後もチェック状態が引き継がれる）

### 実測で得た Jooto API 知見（spec / ガードに反映済み）
- タスクリネームは `PATCH /v1/boards/{board_id}/tasks/{task_id}`（bare パスは 404）
- checked 付きチェックリスト項目作成は API 対応
- **Jooto UI の「削除」は実際にはアーカイブで API には残り続ける**
  → 取得選択規則・冪等判定ともアーカイブ済みタスクを除外するよう修正
- FY26_27/29 の旧タスクはアーカイブ済みで更新 API 404 → リネーム不要と判明
